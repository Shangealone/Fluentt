# FLUENTT v0.1A Backend Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish the FLUENTT monorepo and a testable FastAPI/PostgreSQL backend supporting researcher-provisioned learner accounts, secure authentication, learner preferences, and manually curated language content.

**Architecture:** FastAPI is the single authoritative application gateway. PostgreSQL is the server source of truth; routes remain thin and delegate to service modules. This plan intentionally stops before review scheduling, offline sync, and research-event implementation.

**Tech Stack:** Python 3.13, FastAPI, SQLAlchemy 2.x patterns, Alembic, PostgreSQL 17, Pydantic, PyJWT, pwdlib/Argon2id, pytest, httpx, Docker Compose. Mobile work is handled by Plan B.

**Spec:** `docs/superpowers/specs/2026-09-21-fluentt-v0.1-design.md`

## Global Constraints

- Learner is the only application role in v0.1.
- Public self-registration is disabled.
- Accounts are researcher-provisioned with participant codes and temporary passwords.
- First successful login with a temporary password must force password replacement.
- Passwords are Argon2id-hashed; plaintext passwords and raw tokens must never be logged.
- FastAPI is the only authoritative application gateway.
- PostgreSQL is authoritative server storage.
- English and Tagalog are structurally supported as interface/learning languages.
- Content is manually curated and versioned; no AI-generated content.
- Final ESR, NLP, pronunciation, admin dashboard, and research experiment assignment are out of scope.
- Dependency versions must be locked in `uv.lock` and `pnpm-lock.yaml` once resolved.

## Review Focus

- Duplicate participant codes or emails must fail deterministically instead of silently creating a second account; pinned in Task 3 tests.
- Expired, malformed, or revoked refresh sessions must not mint a new access token; pinned in Task 3 tests.
- An inactive learner must be unable to authenticate or call protected routes; pinned in Task 3 tests.
- Unsupported interface/target-language codes must be rejected server-side; pinned in Task 4 tests.
- Inactive or stale-version learning content must not appear in the default learner content feed; pinned in Task 5 tests.

- [ ] **Step 3: Implement configuration and database session factory**

`backend/app/core/config.py`:

```python
from functools import lru_cache
from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    app_env: str = "development"
    database_url: str
    jwt_secret: str
    access_token_minutes: int = 15
    refresh_token_days: int = 30
    model_config = SettingsConfigDict(env_file=".env", extra="ignore")


@lru_cache
def get_settings() -> Settings:
    return Settings()
```

`backend/app/database/base.py`:

```python
from sqlalchemy.orm import DeclarativeBase


class Base(DeclarativeBase):
    pass
```

`backend/app/database/session.py`:

```python
from collections.abc import Generator
from sqlalchemy import create_engine
from sqlalchemy.orm import Session, sessionmaker
from app.core.config import get_settings

settings = get_settings()
engine = create_engine(settings.database_url, pool_pre_ping=True)
SessionLocal = sessionmaker(bind=engine, autoflush=False, expire_on_commit=False)


def get_db() -> Generator[Session, None, None]:
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

- [ ] **Step 3: Implement auth models and security primitives**

`User` fields must include UUID `id`, unique normalized email, unique `participant_code`, `password_hash`, `must_change_password`, `is_active`, `created_at`, `updated_at`.

`RefreshSession` fields must include UUID `id`, `user_id`, unique `jti`, `token_hash`, `expires_at`, `revoked_at`, `created_at`.

`security.py` must expose:

```python
hash_password(password: str) -> str
verify_password(password: str, encoded: str) -> bool
create_access_token(user_id: str) -> str
create_refresh_token(user_id: str, jti: str) -> str
hash_token(raw_token: str) -> str
```

Use `pwdlib.PasswordHash.recommended()` for Argon2id and SHA-256 for server-side refresh-token fingerprinting. JWTs must include `sub`, `type`, `exp`, and refresh JWTs must also include `jti`.

- [ ] **Step 4: Implement provisioning/reset services before API routes**

Service signatures:

```python
provision_participant(db: Session, *, email: str, participant_code: str, temporary_password: str) -> User
reset_participant_password(db: Session, *, participant_code: str, temporary_password: str) -> User
```

Both operations set `must_change_password=True`. Reset must revoke all active refresh sessions for the participant.

- [ ] **Step 5: Implement API schemas and routes**

Login response must include:

```json
{
  "access_token": "<jwt-access-token>",
  "refresh_token": "<rotating-jwt-refresh-token>",
  "token_type": "bearer",
  "must_change_password": true
}
```

Protected application endpoints must reject a valid token when the user is inactive. Routes other than password-change/logout/refresh must be blocked while `must_change_password` is true.

- [ ] **Step 6: Add revocation/expiry/disabled-account API tests**

Tests must prove:

```text

disabled account -> 401
expired refresh -> 401
revoked refresh -> 401
valid refresh -> rotates session and old refresh becomes unusable
temporary-password user -> protected normal route returns 403 until password changed
```
