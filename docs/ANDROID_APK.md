# Local Android APK

This is a locally signed test build, using Expo's generated debug signing configuration in the release variant. It embeds its JavaScript and assets and does not need Metro. It is not a production deployment or evidence that all phone features have been tested.

## Build prerequisites and fixes

Use Expo SDK 58, Android SDK build-tools 37, NDK 27.1.12297006, CMake 3.22.1 and Java 21. Keep `android/` generated by Expo; do not edit it manually.

The deprecated `expo-av` dependency could not pass release optimization against Expo 58: KeepAwakeManager, AnyTypeProvider and LazyKType were missing. `useAudioRecorder.ts` now uses SDK-compatible `expo-audio` for native recording and playback. The browser's existing MediaRecorder path remains. Background audio and background recording are disabled in app configuration. No scoring or learning-record semantics change.

The explicitly invoked `scripts/android-windows.init.gradle` adapter uses shorter C++ staging paths, bounded compilation pools and explicit shared C++ runtime linkage to address observed Windows Ninja/path and linker failures. It does not run in normal cloud builds. Java's local Unix-domain socket connection failed on this laptop; the invocation below forces its fallback to TCP without changing system settings.

From `apps/mobile/android`, with `JAVA_HOME` and `ANDROID_HOME` set to the local installations:

```powershell
$env:JAVA_TOOL_OPTIONS = '-Djdk.net.unixdomain.tmpdir=C:\fluentt-unavailable-socket-dir -Djava.net.preferIPv4Stack=true'
$env:NODE_ENV = 'production'
$env:CMAKE_BUILD_PARALLEL_LEVEL = '2'
# This local-only address is not a deployed server.
$env:EXPO_PUBLIC_API_URL = 'http://localhost:8000'
.\gradlew.bat app:assembleRelease -I '..\..\..\scripts\android-windows.init.gradle' -x lint -x test --no-daemon --max-workers=2 '-Pkotlin.compiler.execution.strategy=in-process' '-PreactNativeArchitectures=arm64-v8a'
```

Regenerate native configuration after dependency/plugin changes with the installed Expo CLI (`expo prebuild --platform android --no-install` from `apps/mobile`). The expected build output is `apps/mobile/android/app/build/outputs/apk/release/app-release.apk`. Generated native code, logs and signing files remain local.

## Runtime limits

The selected ABI is arm64-v8a, matching the previously connected Samsung SM_A566B. A different ABI requires another build. The backend, PostgreSQL and Azure credentials are not included in the APK. The configured localhost API is laptop-only and cannot provide server services at school or away from the laptop. Android release network restrictions may also block plain HTTP; use an appropriately configured HTTPS backend for standalone live accounts. Offline packaged screens or demo actions are not proof that live classroom/account/history/provider features work offline. English acoustic scoring still requires the configured Azure service; Tagalog remains unscored. Research approval and enrollment gates remain intact.
