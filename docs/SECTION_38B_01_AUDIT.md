## 4. Source findings that constrain implementation

1. **No classroom isolation:** enrollment checks study/student but not designated class. `_resolve_participant_for_user` (`experiment_service.py:886`) checks study/user linkage only. A withdrawn check in several operations does not replace current membership, consent-kind requirements, owning-instructor eligibility and protocol checks.
2. **Generic review cross-context risk:** `spaced_repetition/service.py:25–103,119–149,316–339` contains all personal/classroom/research resolution. Research identity lookups omit study scope; `ReviewEventInput.study_id` exists but is unused there. Research + non-null `class_id` takes the ordinary-classroom branch. Do not solve this by modifying personal/default resolution or populating research `LearningContext.class_id`.
3. **Read paths can author research infrastructure:** experiment status/list and admin groups call `ensure_study_experiment_infrastructure`, which adds groups/configurations/placeholder content for unlocked studies. It returns immediately for locked studies. Do not call these endpoints to “inspect” a real study during this audit; future read contracts must be read-only, with explicit approved authoring/seeding separated.
4. **Enrollment policy not comprehensively enforced:** `check_participant_eligibility` checks profile, date and capacity; `enroll_participant` does not reuse the complete check. Its advisory-lock catch-all suppresses database errors for unit-test compatibility. Transaction/locking guarantees require real PostgreSQL tests; tests using `MockDB` cannot establish them. Student mutation routes also call `commit()` inside the shared authenticated-session context. Review research transaction ownership without altering shared session behavior.
5. **Protocol execution can bypass UI:** list metadata computes unlocked milestones, but direct start/submit paths do not call the same gate, verify server deadlines, or enforce a delayed interval. Attempts use check-then-create without demonstrated database single-attempt concurrency enforcement. A result uniqueness key includes attempt number; it is not by itself a one-completed-attempt policy.
6. **Scoring is independent and unapproved:** research string comparison strips/lowercases responses; it does not reuse the approved objective-exact-v1 contract. Fixed pronunciation scores must never enter empirical analysis as real output. Block instrument/scoring activation until Chapter 3/rubric/model evidence is supplied; do not silently change ordinary grading.
7. **Blinding/provenance gaps:** client-controlled allocation seeds and returned seeds can compromise allocation concealment. Generic due responses expose algorithm name. Analytics assign outcomes to an unsorted/latest group lookup rather than a frozen event-time assignment. No claim of double blinding is justified by a masked label alone.
8. **Mobile research cleanup gap:** `ResearchParticipationView.tsx:69–149` uses mount effects/state updates without focus-scoped late-response invalidation and has hardcoded elapsed duration. A separate research runner must use existing session-generation access and clear state on blur/access loss, without changing the provider/controller or Personal Learning state.
9. **Documentation conflicts are not requirements:** handoff/Section 39 claim three arms and full verification; model/Section 37 implement two conditions. Section 31 labels FIFAKT simulated while other reports call it fully validated. Retention, sample size, delay and level count in source are legacy implementation choices, not newly approved methodology.

These are audit findings only. No defect was repaired in Prompt 01.
